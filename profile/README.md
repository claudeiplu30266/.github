<p>选住宅 IP 服务器，报价单上的参数往往写得漂亮但不告诉你口径：带宽是共享还是独享、并发是连接还是端口、可用率是月度还是年度。结果就是同样写"100M 带宽、500 并发"，两家的实际体验能差出一个量级。这篇按参数逐项拆，把每个数字背后的含义、该怎么问、合理的区间写清楚，最后给一张可以直接填的选型表，谈价时对着填，比听介绍可靠。</p>

<h2>一、带宽：三个数字决定该买多大</h2>
<p>带宽不能凭感觉买。需要先估三个数字：单次请求的平均体积、峰值并发数、以及峰值持续多久。三者相乘再留三成余量，才是该买的带宽。只看"支持多少兆"没有意义，因为共享带宽的实际可用值随邻居变化。</p>

<h3>单次请求到底多大</h3>
<p>网页登录一次大约几百 KB，主要是脚本和样式；一次长对话的流式回复按文本算，两千个汉字约 6 到 8 KB，加上请求头和加密开销，实际传输体积翻倍。真正吃带宽的是附件上传和大段代码粘贴，几十 MB 的文件一上传，瞬时占用就上去了。</p>

<h3>算一遍示例</h3>
<p>假设 20 个账号同时在线，每人每分钟产生一次请求，平均每次 500 KB，那么每秒的带宽需求约为 1.7 Mbps；如果其中两人同时上传 20 MB 的附件，瞬时需求会飙到几十 Mbps。结论是：日常带宽需求不高，但必须为突发的上传预留余量，否则上传时其他人全部变慢。</p>

<h2>二、并发：先分清你要的是"同时在线"还是"同时发起"</h2>
<img src="/tp.png" alt="住宅IP服务器的带宽并发与地区覆盖参数对照">
<p>并发是最容易踩坑的一栏。同一句话在不同服务商那里可能指三种东西：同时在线的会话数、同一秒发起的请求数、以及可用的代理入口数。买之前必须让对方用一句话定义清楚，否则签完合同才发现达不到预期。</p>

<h3>三种口径的实际差异</h3>
<p>同时在线的会话数最宽松，一个浏览器开着十个标签就算十条；同一秒发起的请求数最严格，脚本一跑就容易撞线；代理入口数则是物理限制，与业务并发不是换算关系。做接口调用的团队应该按第二种买，做人工操作的按第一种买就够。</p>

<h3>超限之后的行为要问清</h3>
<p>是排队等待、直接拒绝、还是降级到共享出口。第三种最隐蔽：业务看起来正常，出口地址已经变了。谈的时候要求写进服务说明，出问题时才有依据。</p>

<h2>三、地区覆盖：节点多不等于你要的地区可用</h2>
<p>宣传页上写"覆盖 50 个国家"，实际下单时你会发现想要的那个城市经常缺货。节点数量是库存上限，不是可用量。真正要看的是目标地区的常态库存和补货速度。</p>

<h3>先确认目标地区的库存深度</h3>
<p>直接问：这个城市现在有多少条可用、最近一个月断货过几次、补货周期多长。三个问题问下来，基本能判断是常态备货还是临时调货。临时调货的地址往往刚被回收，历史记录不一定干净。</p>

<h3>地区与账号资料要对得上</h3>
<p>选地区不是越近越好，而是要与账号填写的国家、支付方式所属地区、常用语言保持一致。三者冲突时，即使延迟很低也会带来额外验证。地区选择应该服务于一致性，其次才考虑延迟。</p>

<h2>四、稳定性参数：可用率、切换时间、恢复时长</h2>
<p>这三项决定故障发生时你的损失。可用率决定一年里有多少时间不能用，切换时间决定故障时多久恢复，恢复时长决定恢复后要不要重建环境。</p>

<h3>可用率要换算成小时</h3>
<p>99.5% 按月算约 3.6 小时不可用，99.9% 约 43 分钟。看起来差别不大，但如果这 3.6 小时正好落在你的业务高峰，影响就被放大。谈的时候问清楚统计口径：是否剔除计划维护、是否按单条地址统计。</p>

<h3>切换与恢复要分开看</h3>
<p>切换时间指从故障发生到流量切到备用线路的时间，恢复时长指业务真正可用的时间。前者靠监控与自动切换，后者还包含建连、鉴权、DNS 解析等环节。要求对方给出两个数字，而不是一个笼统的"分钟级"。</p>

<h2>五、把参数填进一张表再谈价</h2>
<p>把所有参数整理成一页，两家放在一起对比，价格才有可比性。空着的格子就是风险点，谈的时候优先补齐空项，而不是先砍价。</p>

<h3>填表的三条原则</h3>
<p>一，只填有书面依据的数字，口头说的标注来源；二，口径不同的项先统一再比，比如把"并发"统一成会话数；三，把不确定项单独列一栏，作为试用期重点验证的对象。</p>

<h3>试用期验证什么</h3>
<p>重点验证三件事：晚高峰的实际带宽、并发到顶时的行为、以及故障切换的真实耗时。三件事都过，再谈长约。价格区间因地区、带宽与独享程度差异较大，本文不列具体报价，实际以当期报价为准，仅供参考。</p>

<h2>常见问答</h2>
<h3>带宽买小了会怎样？</h3>
<p>答：表现为晚高峰整体变慢、上传时其他人卡顿、长回复流式输出断续。带宽不足不会报错，只会让人怀疑线路质量。先用一周的实际流量数据估算峰值，再按峰值上浮三成购买。</p>
<h3>可用率 99.9% 是不是就够用了？</h3>
<p>答：取决于业务对中断的容忍度。按月 43 分钟的不可用，对人工操作为主的场景通常可以接受；对自动化调用则要配合重试与备用线路，否则仍会出现失败。</p>
<h3>节点多的服务商一定更好吗？</h3>
<p>答：不一定。节点多说明覆盖广，但你实际只用一两个地区，其余节点不产生价值。更重要的是目标地区的库存深度与补货速度，这两项直接决定你能不能稳定拿到想要的地址。</p>
<h3>参数都达标了，为什么体验还是一般？</h3>
<p>答：参数只描述上限，不描述波动。晚高峰的抖动、上游互联质量、邻居的占用情况都不在参数表里。这些只能通过连续观测发现，建议在试用期做一周的分时段记录。</p>
